# 前端工程与交互规范（核心摘要与技术栈导航）

## 1. 跨框架通用前端与交互核心原则

1. **视图架构与状态所有权清晰**：按功能域组织视图、导航与请求模块；多角色界面按访问边界与布局差异适度隔离；状态就近管理，仅共享跨组件必需项，是否使用全局状态库由项目复杂度决定。
2. **复用适合项目的 UI 能力**：优先复用已有设计系统、组件库或原生控件，避免重复实现复杂交互；是否引入组件库及覆盖范围由产品形态决定。保持视觉层级、交互状态与可访问性一致，主题通过项目既有样式机制管理。
3. **按不确定性选择交互原型**：体验方向尚不明确或关键交互难以描述时，先用轻量原型获取反馈；要求已明确时，可在授权范围内直接联动修改前后端并验证。
4. **导航与反馈贴合任务**：根据平台习惯、链接访问与流程连续性选择独立路由、弹层或内嵌视图；返回行为符合实际导航语义；操作结果清晰可感知，按影响范围与持续性选择行内提示、Toast、通知区等反馈。
5. **列表与检索按使用场景设计**：围绕用户决策组织摘要、详情和可用状态；根据查询成本、响应时延与筛选流程选择实时防抖或显式提交，并按使用频率组织控件，保持同组交互一致。
6. **有代表性的演示数据（Seed Data）**：需要演示时，准备符合领域特征且覆盖典型状态的数据；按环境与任务选择初始化注入、显式脚本或 Mock，避免覆盖已有数据或在生产环境自动注入。
