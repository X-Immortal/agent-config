# 通用配置管理、动态资源与部署运维细则

本规范提炼跨技术栈的通用配置管理、动静态资源划分、容器化编排与 CI/CD 流水线原则。

## 1. 配置集中化与默认值优先

1. **单一主配置与本地覆盖分离**
   - 使用单一主配置文件集中管理应用的公共配置项；本地开发环境的个人覆盖参数放入独立的本地配置文件（并在构建打包规则中排除本地覆盖文件）。
   - 跨环境（开发、测试、生产）的参数差异统一通过环境变量注入主配置文件，保持配置文件数量精简。
2. **沿用运行时与框架的成熟默认配置**
   - 当操作系统、语言运行时、Web 框架与数据库驱动的默认配置已满足业务需求时，直接沿用默认行为（如默认本地时区、默认时间序列化格式、默认连接池参数），仅声明必要的业务配置项。
   - 既有项目以仓库版本与兼容性约束为基线；新建或获准升级数据库、运行时及基础中间件时，查询官方支持周期与兼容要求，优先选择仍受支持且适合项目的稳定版本或 LTS，并在项目配置中明确版本。

## 2. 环境端口解耦与代理职责分离

1. **服务监听端口与外部映射分别管理**
   - 服务可沿用标准监听端口，宿主机映射按环境与占用情况选择；连接配置反映应用的实际访问路径：
     - 同一容器网络内通过服务名与容器端口连接；
     - 宿主机访问容器服务时使用实际映射端口；
     - 测试环境通过独立网络或可用端口避免冲突，不固定为某个相邻端口。
2. **前端静态托管与 API 反向代理职责清晰**
   - 前端静态资源容器专注于托管构建后的静态文件。
   - 前后端接口转发与路由分发统一由开发环境代理（Dev Server Proxy）或生产环境入口反向代理网关承担，保持各容器职责单一。

## 3. 动态上传资源与代码包隔离

1. **动态文件外置存储**
   - 运行时由管理员或用户动态上传、更新的媒体与附件资源，统一存储在代码包之外的宿主机目录、持久化数据卷（Volume）或对象存储中，避免打包进应用镜像或在前后端重复存放。
   - 随仓库提供的初始演示媒体资源统一放置在外部部署资源目录（如 `deploy/`）中。
2. **统一通过后端服务管理与映射**
   - 本地开发通过本地配置指向外部资源目录，容器化部署将该持久化卷挂载至后端服务容器，由后端的静态资源映射机制或媒体接口统一提供访问控制与读取。
3. **集中声明全局 API 路由前缀**
   - 后端服务的公共路由前缀（如 `/api`）在应用级全局配置或顶层路由器中集中声明一次，使各业务模块的路由定义保持简洁。

## 4. 精简容器化与自动化交付（CI/CD）

1. **匹配项目定位的精简容器编排**
   - 容器构建文件（如 `Dockerfile`）与编排文件聚焦于构建与运行必需的核心指令，保持构建层级清晰、镜像轻便。
   - 数据库初始化建表脚本、种子数据脚本与必要的字符集配置统一收纳在 `deploy/` 目录；按需使用容器官方初始化机制，并将演示种子数据限制在明确启用的开发或演示环境。
2. **直观可靠的 CI/CD 流水线**
   - 流水线沿用仓库的版本固定策略，新建或升级 Action 时核对官方支持与运行环境要求；采用容器交付时，聚焦于核心流程：**代码编译与静态检查 → 构建并推送容器镜像 → 目标服务器拉取镜像并更新编排服务**。
   - 当运维环境端口或服务器编排配置发生调整时，及时将仓库内的部署配置与文档同步至最新状态。
