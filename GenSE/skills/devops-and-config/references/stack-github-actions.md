# 技术栈模块：GitHub Actions CI/CD

本文件为可自由组合的**独立技术栈模块**，适用于采用 GitHub Actions 实现持续集成与持续部署的项目。

## 1. 简洁可读的 Workflow 配置

1. **按仓库策略固定受支持版本**
   - 沿用仓库的 Action 版本与固定方式；新建工作流或获准升级时，查询 Action 官方仓库的发布说明与 README（如 [actions/checkout 发布页](https://github.com/actions/checkout/releases)），核对支持状态、Runner/运行时兼容要求与行为变化，再选用受支持的稳定版本。
   - 根据仓库要求使用主版本标签、精确版本或完整提交 SHA；不将示例版本号当作永久标准，不因使用本 Skill 自动升级，也不擅自放宽已有的 SHA 固定策略。
2. **聚焦核心交付闭环**
   - 流水线围绕核心步骤组织：**代码编译与静态检查 → 构建并推送前后端容器镜像 → 通过远程命令在目标服务器部署目录（如 `~/project`）执行 `docker compose pull && docker compose up -d`**。
   - 流水线复杂度与项目规模匹配，省去非必需的繁琐矩阵或重型扫描阶段。

## 2. 提交规范与配置同步

- 提交标题、前缀与正文沿用仓库近期完整提交信息的风格；仅在仓库已有对应约定时使用 `ci:` 或 `cd:`，不将示例前缀作为统一要求。
- 当服务器实际端口或编排配置发生人工调整时，及时将仓库内的 Compose 文件与 CD 脚本同步至最新状态。
