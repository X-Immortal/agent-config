# 技术栈模块：MySQL

本文件为可自由组合的**独立技术栈模块**，适用于采用 MySQL 作为关系型数据库的项目。

## 1. 版本选型与字符集配置

1. **按支持状态与兼容性选型**
   - 既有项目以仓库声明的版本、驱动与迁移约束为基线，不因使用本 Skill 自动升级。新项目或获准升级时，查询 [MySQL 官方文档](https://dev.mysql.com/doc/) 与[支持周期公告](https://www.mysql.com/support/eol-notice.html)，优先选择满足兼容要求且仍受支持的 LTS 版本。
   - 将核验后的版本明确写入项目依赖或镜像配置；通用 Skill 不固化永久默认版本号，也不以浮动 `latest` 标签替代版本选择。
2. **统一 `utf8mb4` 字符集**
   - 提供显式的 MySQL 字符集配置（服务端与客户端统一设置为 `utf8mb4`），保障中文与多字节字符正常存储与检索。

## 2. 初始化脚本、端口约定与并发控制

1. **初始化建表与种子数据脚本**
   - 将建表脚本（`schema.sql`）与开发环境演示数据脚本统一收纳在部署目录（如 `deploy/`）；无历史数据迁移需求时可通过初始化脚本建表，演示数据按环境需要单独启用。
2. **区分服务端口与宿主机映射端口**
   - MySQL 服务通常使用标准端口 `3306`；宿主机映射端口按环境与占用情况选择。应用在容器网络内连接服务端口，在宿主机连接容器时使用实际映射端口，不将某个测试端口作为全局约定。
3. **约束与并发原子更新**
   - 利用 `CHECK` 约束或无符号/条件更新保障数据不变量（如资源占用量非负且不超过总量）。
   - 并发扣减或状态迁移优先采用带前置条件校验的原子 `UPDATE` 语句并检查受影响行数；多行记录加锁或更新采用一致的顺序（如主键升序）以降低死锁风险。
