# 工程级 Git 工作流与多子代理并行协作

本文件补充完整工程开发场景下的阶段性提交节奏、多子代理 `git worktree` 并行隔离、主分支基线切换及仓库整洁与归档规范（日常基础分支命名与提交风格见根 `AGENTS.md`）。

## 1. 功能切片提交节奏与分批暂存

1. **按逻辑里程碑提交**
   - 每完成一个逻辑清晰的功能切片、基础设施底座或文档评审阶段，经对应层级的验证后执行一次提交，使 Git 历史真实反映工程演进过程。
2. **分批提交时的精准暂存**
   - 当工作区同时存在已完成模块与未完成探索（如“先提交设计文档和管理端，首页改动先保留”）时，按明确文件路径执行 `git add <files>`，保持未完成部分留在工作区。

## 2. 子代理（Subagent）并行开发与 Worktree 管理

当多个待开发模块边界清晰、接口契约稳定且互不依赖时，可通过子代理并行开发：

1. **Git Worktree 隔离**
   - 基于 `git worktree` 为每个子代理分配独立工作目录与独立分支，避免多代理并发读写同一工作树引发冲突。
2. **继承模型配置与工程规范**
   - 子代理继承主代理的高能力模型配置。
   - 派发任务时向子代理传递完整自包含的上下文（目标行为、模块边界、完成判据、验证方式与提交规范）。
3. **主代理审查合入与回收**
   - 子代理完成后，由主代理审查代码质量、整合分支并运行集中集成验证。
   - 分支合入当前主开发版本后，及时移除已完成的 `git worktree` 与临时分支。

## 3. 分支整合与主分支基线切换

1. **保持清晰的整合历史**
   - 整合分支或切换主分支指向时，按当次明确授权的整合策略（变基、快进合并或移动分支指针）执行；涉及历史重写时先核对影响范围与可恢复位置，不将其他项目的主分支重置方式作为默认流程。
2. **远端同步**
   - 远端推送按当次显式指令执行；已授权提交后同步推送时，按约定完成同步。

## 4. 仓库卫生、忽略规则与归档打包

1. **分层配置 `.gitignore` 与清理占位文件**
   - 按项目根目录及前后端子工程分层维护 `.gitignore`，将本地开发覆盖配置（如 `application-local.yml`）、构建产物及辅助插件生成的本地隐藏目录纳入忽略规则。
   - 当目录内已有受 Git 追踪的实际文件后，及时清理早期用于占位的 `.gitkeep`。
2. **清理临时容器与环境产物**
   - 阶段验证或构建测试结束后，及时清理验证过程中产生的临时容器、临时镜像与未追踪的临时文件。
3. **基于 Git 追踪列表打包交付**
   - 当需要将仓库打包为压缩包交付时，基于 Git 当前最新已追踪文件列表导出（如使用 `git archive`），并在打包前确认所有最新改动均已提交入库，确保归档产物完整且不含未追踪的本地文件。
